# open-tx-isp: where the driver differs from the vendor module

Items where the open kernel driver deliberately behaves differently from the
vendor `tx-isp-*.ko` (not bug fixes, which are in [CHANGELOG.md](../CHANGELOG.md)).
Each item names the switch that restores the vendor behaviour where one exists.

| Change | SoC | Default | Vendor behaviour back | Why | Status |
|---|---|---|---|---|---|
| No `dump_stack()` after level >= 2 ISP messages (`isp_printf`) | T21 | off | module parameter `warn_stack=1` (runtime, `/sys/module/tx_isp_t21/parameters/warn_stack`) | The vendor prints a full stack after every warning/error message: a console flood of about 100 ms per stack at 115200 baud, in ISP paths. The message itself is unchanged. | 2026-11-06, device A/B on cam-D (T21) |
| Bring-up trace parameters not built (`t20_trace`, `t20_runtime_trace` / `t10_runtime_trace`, `t20_trace_events`) | T10, T20 | not built | build with `TX_ISP_TRACE=y` | Not vendor parameters (our bring-up traces); about -10 KiB module RAM. Kernel 3.10 refuses to load a module given an unknown parameter, so no load script may pass them; none does (checked 2026-11-06: OpenIMP, the streamer, the thingino package and user overlay, `/etc/modules.d` on the T10/T20 test cameras). | 2026-11-06, device A/B on T10 and T20 |
| A tuning (IQ) bin is checked before it replaces the tables in use (version, header flags, both CRCs, tables in bounds, firmware table space; `tx-isp-param-validate.h`) | T10, T20 | on | none (no switch) | The vendor loader points the day/night tables into the new file before checking it, so a rejected or truncated file leaves tables that point into freed or bad data. Now a rejected file keeps the tables that were in use. Host test `tx_isp_t20_param_validate_test`. | 2026-11-07 (#231 L6), device re-init twice on T10 and T20 by runtime module swap |
| AE correction-curve flip guard: a one-step change of the IQ AE-correction curve is held until the exposure moved 1/16 stop (`t20_ae_flip_guard`, `tx_isp_t20_firmware.c` / `tx_isp_t20_ae_max.h`) | T10, T20 | on | module parameter `t20_ae_flip_guard=0` | At some scene brightness the u8 curve value flips by one step every few frames; the vendor (and the open stack with only the vendor-equal gain hysteresis) then keeps cycling the ISP digital gain, ~0.65 Y p-p frame brightness. With the guard the picture settles (0.28 Y p-p on the T10, openimp #267). | 2026-11-11, user OK; T10 light box measured with the guard (default-on build not separately device-tested yet) |
| RAW ring (IMP_ISP_RAW_RwControl) stopped when the tuning fd that enabled it is released without a disable (close or process death) | T41 | on (ring served by default, `t41_raw_ring=0` turns it off) | none (no switch) | The vendor leaves the ISP front end fed by RDMA (picture frozen) and the WDMA writing into rmem the dead process no longer owns; its disable would wait for an RDMA frame that never comes. User OK 2026-11-11 (openimp #320). | 2026-11-11, T41 (gc5603): kill -9 while the ring runs -> ring stopped on release, stream torn down, 0 oops |
| RAW ring teardown and disable limit (openimp #345): `tisp_deinit` stops a ring still on, wakes and drains the RAW sleepers (they get -ENODEV) before `rpars` is freed; the RAW disable waits at most `t41_raw_disable_ms` for an RDMA frame done; enable buffers outside rmem are refused (-EINVAL); a VIC-done wait before any arm sleeps on an initialised completion | T41 | on | `t41_raw_disable_ms=0` (vendor: wait without limit); the others have no switch | The vendor frees `rpars` under a sleeping RAW reader (use after free at its exit), its disable sleeps for ever under the tuning mutex when no frame was handed back (every tuning ioctl of the streamer blocks), it queues any user address into the WDMA, and 0xc0045432 before 0xc0045431 sleeps on a zeroed wait list. Same class as the fd-release stop (user OK 2026-11-11). | 2026-11-11, T41 (gc5603): 3/3 disables with no frame handed back return after 1.1 s (GetBrightness works), ISP teardown with the ring on and a sleeping reader (library without the stop) -> ring stopped, reader got -ENODEV, 0 oops; full rawvic case 30/30 |
| IMP_ISP_WDR_OPEN in linear mode (ioctl 0xc0045432) keeps the stream running: the open module stores the WDR byte and returns 0 like the vendor, frames continue | T40 | on | none (no switch) | The vendor returns 0 too but then delivers 0 frames; the open stream keeps 21 fps on the Eufy T40 test camera (user decision 2026-11-11, #324) | 2026-11-11, Eufy T40XP: `IMP_ISP_WDR_OPEN` (LINEAR) returns 0 and the stream keeps running (#322 SetPreDqtime fixed in the same build) |
| Module parameter `mdns_ref_hold` (bit 0 = hold the temporal-NR reference fields, T23 also writes `b_min` as 0xffffffff): the MDNS register writer keeps the channel-0 reference weights and gates at their maximum, so a picture an application wrote into the reference stays visible (OpenIMP test pattern mode 5 sets it while it runs and clears it at the end) | T23, T41 | 0 (off) | none needed (parameter off = vendor writer) | The vendor has no way to hold a known picture inside the ISP; each gain-step rewrite of the MDNS fields let live picture into the reference. Test aid, off unless an application sets it | T23 night U/V SSIM 0.97/0.98, T41 night Y 0.92 (device, 2026-11-11) |
| Sensor flip that the sensor cannot do stays in the ISP: the kernel-7 V4L2 sensor bridge returns -ENOTSUPP for TX_ISP_EVENT_SENSOR_VFLIP when the sensor driver has neither a hflip nor a vflip control, and `apical_isp_hvflip_update` (shvflip == 1) keeps both axes in the MSCA mask and the LSC mesh unflipped when the sensor flip fails | T31 | on | none (no switch) | The vendor has no V4L2 bridge; its flip path drops V from the MSCA mask even when the sensor did not flip, so a sensor without flip support lost the vertical flip while the call reported success (openimp #251 L5, user decision 2026-11-11) | 2026-11-11, k7 cross-build; device check on the k7 T31X pending |
