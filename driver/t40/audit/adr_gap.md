# T40 ADR (highlight compression, TOP bit 7): chain check

Desk check against the OEM sc830ai module (t40prod `tx-isp-t40.ko`). No device run.

## Findings in the current driver

- TOP bit 7 is never cleared: there is no `BIT(7)` in the gates or force paths, and the base value
  0x7fffeeff keeps it set. So ADR is bypassed in hardware on every profile. The sc830ai bin wants
  ADR active in the linear set (`flags[7]=0`) and bypassed in the WDR set (1).
- Init: `regtrace_tisp_adr_main_init_direct` is hand-written (regtrace_* refresh / base_pars
  replacements). The parts that remain lifted are defective:
  - `func_gauss_local` is `return 0` in every build (REGTRACE branch), so the Gauss table stays empty.
  - `func_adr_reg_write_one` / `_5x5`: the final `jr.hb t9` tail call to `system_reg_write` is an
    unmatched fragment, so the last register write is lost (e.g. base+72, value & 0x1fff).
- Per frame (ISR bit 9 -> event 2 -> `tisp_adr_main_process` -> algorithm / ev_func /
  Tiziano_adr_fpga / subsection_* -> writers): the whole chain is lifted (fragment_seed /
  model_output) with unmatched `madd`/`mflo` (`tiziano_adr_5x5_out`), `div` (`tiziano_adr_base_pars`),
  14 unmatched fragments in `tiziano_adr_5x5_init`, and pointer arithmetic in `ev_func`.
- Object sizes smaller than OEM: `adr_gauss_local` 4 vs 96 B (written by the init),
  `adr_cut_base_up` 4 vs 44 B, `width_adr`/`height_adr`/`count_adr_test` 4 vs 8 B.
  `adr_ev`, `adr_ev_top`, `adr_mlock`, `adr_tgain_changed` and `adr_version_num` do not exist.
- The ISR fan-out has a forced path (`isp_stats_fanout_adr_status0_mask`) that calls
  `irq_func_cb[9]` without status bit 9. That matches the dark picture in DeepSeek's boot B.

## Patch: literal OEM chain behind `t40_adr_on` (default 0)

- `tx_isp_t40_adr_lit.inc`, generated by `tools/gen_t40_adr_lit.py`: 36 OEM functions (init with all
  refresh / base_pars / 5x5 / gauss helpers, ISR, process, algorithm, ev_func, fpga, subsection,
  fix_point, writers) translated literally. 0 unmapped addresses, 0 unhandled opcodes.
- `tools/mips2c_literal.py` extensions:
  - mult/multu/madd/maddu/msub/mtlo/mthi.
  - Full HI16/LO16 section addresses resolved against the OEM symbol table (.bss/.data/.rodata;
    all 1857 .bss HI16 are 0 in this module).
  - Optional runtime call dispatch.
  - Regression: the SDNS/CDNS/YSP lit ports regenerate unchanged.
- State: 70 ADR objects are private (`adrlit_*`, OEM sizes, OEM .data / anonymous .rodata initial
  bytes; no pointer relocations inside them). Only `tparamsN` and `tispinfo` (same size) are shared.
- Calls: every `jalr` goes through `adrlit_dispatch()` on the register value. Internal functions go
  to their `_lit` version; kernel and driver services are wrapped (vmalloc, mutex, dma_cache_sync,
  event push / set_cb, irq_func_set, libgcc 64-bit helpers). Unknown targets are counted
  (`adr_lit_bad_call`, `adr_lit_bad_target`) and return 0.
- Stack: one emulated MIPS stack per entry context (init / ISR / event), 6 KiB each. The deepest
  OEM nesting is 1672 B (init) and 1568 B (process), so stack arguments (fix_point_div,
  func_local_info, subsection_*) reach the callee as in the OEM.
- Activation: only with `t40_adr_on=1` and `t40_gates_oem_offset=1`. Block init then runs
  `tisp_adr_main_init_lit` instead of the direct init. That registers the lit ISR for bit 9 and the
  lit process for event 2. TOP bit 7 is cleared only when the init returned 0 (and not held by
  `t40_force_bypass`).
- Guard: while the lit chain is active, the forced fan-out call is blocked (`adr_lit_forced_blocked`).
  The ISR runs only on its own status bit 9, the process only on event 2.
- Read-only: `adr_lit_init_ret`, `adr_lit_isr_count`, `adr_lit_process_count`, `adr_lit_bad_call`.

## Limits / follow-ups

- Day/night: the OEM `tisp_adr_dn_params_refresh` is not called on a bank switch. ADR keeps its
  day-bank parameters, and bit 7 keeps its state.
- Re-init (stream restart) allocates the OEM buffers again without the OEM deinit (leak per restart
  while `t40_adr_on=1`).
- Unrelated, seen while checking the translator: in the existing lit files, `tisp_clm_wdr_en`,
  `tisp_dmsc_all_reg_refresh` and `ispcore_interrupt_service_routine` call other functions than the
  same functions in the sc830ai production module. Either another vendor version or a hand edit;
  worth a look.
